# MCP servers and plugins for Claude Code: real-world usefulness (notes compiled 16 November 2026)

Evidence labels used on every finding:
**(a)** vendor or maintainer claim, **(b)** independent measurement or study, **(c)** experienced-practitioner report, **(d)** anecdote (including single-user measurements, forum comments, GitHub issues).
Every source cited was fetched and read unless explicitly marked "SNIPPET ONLY". Source dates are given because this ecosystem changes fast; anything from 2025 about context cost predates Claude Code's default-on tool search and is flagged where relevant.

---

## 1. Context cost: how many tokens do MCP tool definitions consume, and how much do tool search and "code execution with MCP" reduce that?

### Takeaway
Before deferred loading, popular servers cost roughly 8k–26k tokens each just for tool definitions (GitHub MCP ~18k–26k, Playwright MCP ~13.7k, Chrome DevTools MCP ~18k), and multi-server setups were measured at 55k–67k tokens before the first prompt. Claude Code now defers MCP tool definitions by default (only tool names and server instructions load at start), which Anthropic says cuts definition overhead by about 85%, but this does not reduce the cost of tool *results* (for example browser snapshots), and I found no independent before/after measurement of Claude Code's own tool search.

### Cited Findings

Measured definition costs (pre-tool-search era)
- (a) Anthropic's own figures for a five-server setup: "GitHub: 35 tools (~26K tokens)", "Slack: 11 tools (~21K tokens)", "Sentry: 5 tools (~3K tokens)", "Grafana: 5 tools (~3K tokens)", "Splunk: 2 tools (~2K tokens)" = "58 tools consuming approximately 55K tokens before the conversation even starts"; Jira "alone uses ~17K tokens"; "At Anthropic, we've seen tool definitions consume 134K tokens before optimization." Dated 24 Nov 2025. — [Anthropic Engineering: advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)
- (d, single-user `/context` measurement) Claude Code issue opened 10 Nov 2025: seven MCP servers consumed 67.3k tokens of tool definitions (33.7% of a 200k window); GitHub MCP (27 tools) ~18k tokens; 550–850 tokens per tool; removing four servers cut it to 42.6k (21.3%). The issue was closed by a bot as a duplicate with no staff reply and only one reaction, so it is one data point, not a consensus. — [anthropics/claude-code issue #11364](https://github.com/anthropics/claude-code/issues/11364)
- (c, with own measurement) Mario Zechner, 2 Nov 2025: "Playwright MCP has 21 tools using 13.7k tokens (6.8% of Claude's context)"; "Chrome DevTools MCP has 26 tools using 18.0k tokens (9.0%)"; his CLI-plus-README replacement: "this README has a whopping 225 tokens." — [Zechner: What if you don't need MCP at all?](https://mariozechner.at/posts/2025-11-02-what-if-you-dont-need-mcp/)
- (c) Armin Ronacher, 13 Dec 2025: loading the Sentry MCP upfront costs "around 8k tokens out of the box." — [Ronacher: Skills vs Dynamic MCP Loadouts](https://lucumr.pocoo.org/2025/12/13/skills-vs-mcp/)
- (c) Simon Willison, 16 Oct 2025: "GitHub's official MCP on its own famously consumes tens of thousands of tokens of context, and once you've added a few more to that there's precious little space left for the LLM to actually do useful work." — [Willison: Claude Skills](https://simonwillison.net/2025/Oct/16/claude-skills/)
- (a) GitHub, 10 Dec 2025: "we found that loading 3-10 of the most used tools into the context window can lead to a ~60-90% reduction" in context usage versus the default toolsets; the default `repos` + `pull_request` toolsets alone total 27 tools. — [GitHub changelog 2025-12-10](https://github.blog/changelog/2025-12-10-the-github-mcp-server-adds-support-for-tool-specific-configuration-and-more)
- (a, third-party maintainer) Serena's docs state that Claude Code's *built-in* tool descriptions "take almost 16k tokens" (their figure, not Anthropic's; undated docs page read Nov 2026). — [Serena docs: clients](https://oraios.github.io/serena/02-usage/030_clients.html)
- (b, academic preprint, limited relevance) MCPGauge (arXiv, 18 Aug 2025; six LLMs incl. Claude 4, 30 MCP tool suites, ~20,000 API calls): input-token volume rose 3.25× to 236.5× with MCP attached, and accuracy fell on average 9.5% (code generation −17.0%). Important caveat: tasks were QA-style and HumanEval/MBPP, not agentic software-engineering workflows, and it predates tool search. — [arXiv 2508.12566 abstract](https://arxiv.org/abs/2508.12566); [full text](https://arxiv.org/html/2508.12566v1)

Tool search / deferred loading
- (a) Claude Code docs (read Nov 2026): "Tool search keeps MCP context usage low by deferring tool definitions until Claude needs them. Only tool names and server instructions load at session start, so adding more MCP servers has minimal impact on your context window." "Tool search is enabled by default: MCP tools are deferred and discovered on demand." — [Claude Code docs: MCP](https://code.claude.com/docs/en/mcp)
- (a) Exceptions in the same docs: tool search applies on "Claude Opus 4, Claude Sonnet 4, Claude Haiku 4.5, and later models"; earlier models load everything upfront; not supported on Microsoft Foundry deployments hosted on Azure; `ENABLE_TOOL_SEARCH=false` disables it; `ENABLE_TOOL_SEARCH=auto` defers only once definitions reach 10% of the context window; a server with `"alwaysLoad": true` loads upfront regardless ("each upfront tool consumes context that would otherwise be available for your conversation"). — [Claude Code docs: MCP](https://code.claude.com/docs/en/mcp)
- (a) Anthropic's numbers for the API-level Tool Search Tool (24 Nov 2025): traditional approach "~72K tokens for 50+ MCP tools", "~77K tokens before any work begins"; with tool search "~8.7K tokens, preserving 95% of context window"; "This represents an 85% reduction in token usage". Accuracy on Anthropic's internal MCP evals: "Opus 4 improved from 49% to 74%, and Opus 4.5 improved from 79.5% to 88.1% with Tool Search Tool enabled." (Note: 77K to 8.7K is arithmetically ~89%, so the post's own figures are slightly inconsistent.) — [Anthropic Engineering: advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)
- (c) Critique of deferred loading from Ronacher (13 Dec 2025): tool definitions "still have to be static for the entire conversation"; changing them loses the prompt cache ("pay full token rates plus cache write cost, compared to cache read"); MCP tool descriptions are "both too long to eagerly load it, and too short to really tell the agent how to use it"; and "MCP servers keep changing their tool descriptions at will". — [Ronacher: Skills vs Dynamic MCP Loadouts](https://lucumr.pocoo.org/2025/12/13/skills-vs-mcp/)
- (a, third-party maintainer) A downside of deferral reported by Serena's maintainers: because of dynamic tool loading the agent may "fail to make proper use of Serena's tools, either by failing to load them in the beginning" or by drifting in long sessions. — [Serena docs: clients](https://oraios.github.io/serena/02-usage/030_clients.html)
- (c, maintainer of Sentry MCP) David Cramer, 10 Nov 2026: "One of the most important and still common differences is tool search"; harnesses now defer tool loading but implementations of search vary across clients. — [Sentry blog: MCP or CLI? Yes.](https://blog.sentry.io/mcp-or-cli)

Tool-result (not definition) cost
- (a) Claude Code "displays a warning when MCP tool output exceeds 10,000 tokens and limits output to 25,000 tokens by default" (`MAX_MCP_OUTPUT_TOKENS`). — [Claude Code docs: MCP](https://code.claude.com/docs/en/mcp)
- (a) Anthropic names intermediate results as the second cost: "Every intermediate result must pass through the model"; a 2-hour meeting transcript passed through twice "could mean processing an additional 50,000 tokens." — [Anthropic Engineering: code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp)

Code execution with MCP / programmatic tool calling
- (a) Anthropic, 4 Nov 2025 (Adam Jones, Conor Kelly): presenting MCP servers as code APIs that the agent calls from a sandbox "reduces the token usage from 150,000 tokens to 2,000 tokens—a time and cost saving of 98.7%". This is an illustrative scenario in the post, not a published benchmark. Stated downside: "Running agent-generated code requires a secure execution environment" and "These infrastructure requirements add operational overhead and security considerations". — [Anthropic Engineering: code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp)
- (a) Programmatic Tool Calling (API feature, 24 Nov 2025): "Average usage dropped from 43,588 to 27,297 tokens, a 37% reduction on complex research tasks"; internal knowledge retrieval 25.6% to 28.5%; GIA 46.5% to 51.2%. — [Anthropic Engineering: advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)

### Inferences
- The 2025 "MCP eats your context window" figures are real but partly outdated for current Claude Code: with default deferral the standing cost of an idle MCP server is now tool names plus server instructions, not full schemas. The critique still fully applies when tool search is off (older models, Azure Foundry, `ENABLE_TOOL_SEARCH=false`, `alwaysLoad`), and to tool outputs.
- The remaining context risk has shifted from definitions to results: accessibility snapshots, issue lists and log dumps flow through the model regardless of deferral. CLI tools avoid this because output can be piped, filtered or written to a file.
- All large "percentage saved" numbers (85%, 98.7%, 60–90%) are vendor claims on vendor-chosen scenarios. The only independent numbers are baseline costs (Zechner; one GitHub issue), not savings.
- Deferral introduces a new failure mode (the model never searches for the tool), which Serena's maintainers and Cramer both describe; fewer tokens does not automatically mean better tool use.

### Gaps
- No independent before/after measurement of Claude Code's built-in MCP tool search was found. Secondary blogs quote 46.9% ("51K to 8.5K") and 95% figures, but I saw those only in search snippets and could not trace them to a primary source (SNIPPET ONLY; not cited).
- I could not confirm from a primary source in which Claude Code version tool search became default (search snippets mention v2.1.7 in January 2026 for the 10% auto threshold; SNIPPET ONLY).
- Geoffrey Huntley's post on MCP context allocations (23 Aug 2025) is paywalled; only the introduction was readable, so his specific token numbers are not cited. Visible text notes "Cursor caps the number of MCP tools that can be enabled in Cursor to just 40 tools". — [ghuntley.com/allocations](https://ghuntley.com/allocations/)
- Whether Claude Code itself natively implements the "code execution with MCP" pattern (as opposed to the API/Agent SDK) was not established from the pages read.

## 2. MCP versus CLI: do plain command-line tools work as well or better for coding agents?

### Takeaway
The most credible practitioners with public track records (Ronacher, Willison, Zechner) have largely moved from MCP servers to CLI tools plus skills for coding-agent work, citing context cost, composability and debuggability; the one controlled practitioner benchmark found MCP versus CLI "a wash" when the tool itself is well designed. The strongest pro-MCP arguments are not about coding quality at all: native discoverability, remote OAuth, credential isolation and audit for teams, and cases where no good CLI exists.

### Cited Findings

CLI/code side
- (c) Armin Ronacher, 3 Jul 2025: MCP "isn't truly composable" and "demands too much context"; "every tool invocation consumes even more context than simply writing and running code"; "It's always a gamble and incredibly hard to debug." He suggests comparing GitHub MCP with `gh`: you will "almost certainly find the latter uses context far more efficiently" (no measurement given). Concession: "I find it very hard to replace Playwright with a code approach for all cases." — [Ronacher: Tools: Code Is All You Need](https://lucumr.pocoo.org/2025/7/3/tools/)
- (c) Ronacher, 13 Dec 2025: "I've been moving all my MCPs to skills, including the remaining one I still used: the Sentry MCP"; he replaced Playwright MCP with a Playwright skill; "I tend to go with what is easiest, which is to ask the agent to write its own tools as a skill." — [Ronacher: Skills vs Dynamic MCP Loadouts](https://lucumr.pocoo.org/2025/12/13/skills-vs-mcp/)
- (c) Simon Willison, 16 Oct 2025: "Almost everything I might achieve with an MCP can be handled by a CLI tool instead." LLMs can run `cli-tool --help`, so "you don't have to spend many tokens describing how to use them." "Skills have exactly the same advantage, only now I don't even need to implement a new CLI tool." — [Willison: Claude Skills](https://simonwillison.net/2025/Oct/16/claude-skills/)
- (c) Mario Zechner, 2 Nov 2025: "MCP servers also aren't composable"; CLI output can be saved to files or chained in one Bash command instead of passing through the context; tools are trivially editable (a new cookies tool "took not even a minute"). His caveat: "With great power comes great responsibility though", you must maintain the tools yourself, and Playwright MCP and Chrome DevTools MCP are "fine". — [Zechner: What if you don't need MCP at all?](https://mariozechner.at/posts/2025-11-02-what-if-you-dont-need-mcp/)
- (a) Microsoft's own Playwright MCP README now says that for coding agents "you might benefit from using the CLI+SKILLS instead", because CLI invocations avoid loading large tool schemas; the Playwright CLI README says "If you are using coding agents, that is the best fit". A maintainer recommending against its own MCP server for this use case is notable. — [microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp); [microsoft/playwright-cli](https://github.com/microsoft/playwright-cli)
- (a) Upstash now ships Context7 in a "CLI + Skills" mode that needs no MCP server, alongside the MCP mode. — [upstash/context7](https://github.com/upstash/context7)

Measured comparison
- (b/c, practitioner benchmark, self-described as not fully scientific) Zechner, 15 Aug 2025: 120 Claude Code runs (3 tasks × 4 tools × 10 repetitions) comparing the same terminal tool as MCP server and as CLI, plus tmux and screen. Both MCP and CLI variants hit 100% success; MCP was 23% faster (51m vs 66m) and 2.5% cheaper ($19.45 vs $19.95) overall. Conclusion: "MCP vs CLI truly is a wash"; "The protocol is just plumbing"; "a lot of MCPs could have been CLI invocations". Caveat from the author: "My aim wasn't to create a fully scientific evaluation." — [Zechner: MCP vs CLI benchmark](https://mariozechner.at/posts/2025-08-15-mcp-vs-cli/)

MCP side
- (c, but also maintainer of the Sentry MCP server) David Cramer, 10 Nov 2026: MCP is still "the superior agentic tooling" because "The advantage of the MCP is it's native", so the agent discovers it without being told a CLI exists; but CLI wins when a filesystem is needed (fetch raw logs, grep, paginate): "That cannot be done with MCP, unless you (very inefficiently) were to try to implement those same behaviors on the server." Sentry ships both. — [Sentry blog: MCP or CLI? Yes.](https://blog.sentry.io/mcp-or-cli)
- (a, vendor selling MCP infrastructure) Stacklok, 28 Apr 2026: with remote MCP "The MCP server, not the agent's host environment, holds the credentials"; per-user OAuth 2.1 gives scoped, revocable access and "Each tool invocation is attributable to the individual who authorized it." Concessions: "The token efficiency argument has real data behind it" and "CLI wins on token cost for local, familiar tools." — [Stacklok: MCP vs CLI Tools: Why Security Changes the Answer](https://stacklok.com/blog/mcp-vs-cli-tools-why-security-changes-the-answer/)
- (c, dated) Gergely Orosz, 8 Apr 2025: connecting a PostgreSQL MCP server let the LLM self-correct table and column names, a "game changer"; but protection "looks woefully fragile" and there were "many worrying security gaps". Paywalled after section 4; written before coding-agent CLIs matured, so treat as early-era enthusiasm. — [Pragmatic Engineer: MCP Protocol](https://newsletter.pragmaticengineer.com/p/mcp)
- (a) Anthropic's docs position MCP as the way to "read and act on that system directly", and the plugin system packages MCP servers as a first-class component. — [Claude Code docs: MCP](https://code.claude.com/docs/en/mcp); [Claude Code docs: Plugins overview](https://code.claude.com/docs/en/plugins)

### Inferences
- For a developer whose agent already has a shell, a mature CLI (`gh`, `playwright-cli`, `ctx7`, `sentry`) is at least as effective as the matching MCP server for local coding work, and the maintainers of Playwright and Context7 have effectively conceded this by shipping CLI+skill modes.
- MCP's defensible niche is (1) services with no good CLI, (2) remote servers with OAuth where credentials should not sit on the developer's machine, (3) team-wide, centrally governed integrations, and (4) surfaces without a shell (cloud chat, claude.ai connectors).
- The debate is now more about tool design than protocol: Zechner's benchmark and Cramer's post agree that a well-designed tool performs similarly through either channel.
- Voices on the pro-MCP side that I could find are mostly vendors with a commercial interest (Stacklok, Sentry as a maintainer); the sceptics are independent practitioners. That asymmetry itself is a signal, though the sceptics are all solo/power users rather than enterprise administrators.

### Gaps
- No rigorous, multi-task, independent benchmark comparing MCP servers with their CLI equivalents inside Claude Code on real software-engineering tasks was found; Zechner's is one tool, three tasks.
- A direct `gh` CLI versus GitHub MCP token/accuracy measurement was not found; Ronacher asserts the result without data.
- Reddit (r/ClaudeAI, r/ClaudeCode) threads could not be fetched in this environment, so community volume and consistency there is unassessed.

## 3. Context7 (Upstash)

### Takeaway
Context7 fetches current, version-specific library documentation into the agent's context; the only quantitative evidence that it reduces outdated-API usage is the vendor's own October 2026 test (old-API-only answers fell from 43/94 to 9/94), which also showed plain web search (Exa) doing about as well with roughly ten times more tokens. It has a documented supply-chain vulnerability (ContextCrush, fixed February 2026, CVE issued August 2026), a closed-source backend with community-contributed content, and a free tier of 1,000 calls per month.

### Cited Findings
- (a) What it does: LLMs "rely on outdated or generic information about the libraries you use"; Context7 "pulls up-to-date, version-specific documentation and code examples straight from the source". MCP tools: `resolve-library-id` and `query-docs`. A "CLI + Skills" mode (`ctx7 library`, `ctx7 docs`) works without MCP. — [upstash/context7 README](https://github.com/upstash/context7)
- (a) Limits stated by the maintainer: projects are "community-contributed" and Context7 cannot "guarantee the accuracy, completeness, or security of all library documentation"; the repo is MIT but only contains the MCP server, while the "API backend, parsing engine, and crawling engine" are private. — [upstash/context7 README](https://github.com/upstash/context7)
- (a, vendor-run test; treat as best case) Context7's own guide, published 22 Oct 2026: 47 real 2026 API renames/removals across 34 libraries, each asked twice (94 responses), model stated as "Claude Sonnet 5.5". Without a docs tool: 43 of 94 used only the old API, 39 only the current API. With Context7: 9 of 94 old-only, 66 current-only. With Exa web search: 7 of 94 old-only, 65 current-only. Median result size: Context7 786 tokens versus Exa 8,550 tokens; the Context7 agent used about 4.6× fewer input tokens overall (454K vs 2.08M). Admitted limits: Context7 returned "only old API docs in 12 of the 94 queries"; 17% of Context7 results contained an old API name; naming the major version raised current-only results from 37% to 55%; agents may skip docs tools unless a rule tells them to call one; only public docs are indexed on the free tier. — [Context7 guide: why AI coding agents use outdated APIs](https://context7.com/guides/why-ai-coding-agents-use-outdated-apis)
- (c) Thoughtworks Technology Radar placed Context7 in **Trial** (Volume 35, 5 Nov 2025): in their experience it substantially reduced code hallucinations and reliance on stale training data. Caveat: the page says the blip is "not on the current edition of the Radar", so the assessment may be stale. — [Thoughtworks Radar: Context7](https://www.thoughtworks.com/radar/tools/context7)
- (d) A Hacker News commenter (3 Sep 2025) reported that "Even with Serena, Context7, and other MCPs" Claude Code's self-correction loop was not faster for them. — [HN Algolia comment search](https://hn.algolia.com/api/v1/search?query=serena%20mcp%20claude%20code&tags=comment&hitsPerPage=30)
- (a) Pricing as shown on the plans page (read Nov 2026): Free $0 with 1,000 API calls/month, blocked at the limit with 20 bonus calls per day, no private repos; Pro $10 per seat/month with 2,000 calls per seat and $5 per 1,000 overage; private-repo parsing $5 per 1M tokens; Enterprise custom. No per-second rate limits are published. — [context7.com/plans](https://context7.com/plans)
- (b) Security incident "ContextCrush" (Noma Labs, published 5 Mar 2026): the "Custom Rules" / AI Instructions feature let any library owner publish text that was "served verbatim through Context7's MCP server to every user who queried that library"; anyone can register a library, and trust signals (GitHub stars, account age) could be gamed. The PoC had a coding assistant read `.env` files, post them to an attacker-controlled GitHub issue, and delete local files. Timeline: reported 18 Feb 2026, fix deployed 23 Feb 2026. Noma cites "approximately 50,000 stars and more than 8 million npm downloads" for Context7. — [Noma Security: ContextCrush](https://noma.security/blog/contextcrush-context7-the-mcp-server-vulnerability/)
- (a) Upstash's account: Custom Rules were disabled, then re-enabled with "an injection check before saving any rule"; "No exploitation in the wild was observed." VulnCheck published CVE-2026-75130 on 18 Aug 2026 for the same flaw listing Context7 "through 2.1.2" with no fixed version; Context7 disputes that framing because the fix was server-side. — [Context7: ContextCrush, what happened and what we changed](https://context7.com/guides/contextcrush)
- (a) Context7 is listed as a plugin with the "Anthropic verified" badge on Claude Marketplace (page read Nov 2026). — [Claude Marketplace: plugins](https://claude.com/marketplace/plugins)

### Inferences
- The vendor's own data shows that the benefit comes from "have a docs lookup step" rather than from Context7 specifically: a generic web search achieved near-identical correctness. Context7's differentiator is token efficiency (roughly 10× smaller results), not accuracy. Claude Code already has WebSearch/WebFetch, so the marginal gain is smaller than marketing implies.
- Benefit is concentrated on fast-moving libraries released after the model's training cutoff; for stable, well-known APIs it adds a round trip and third-party content for little gain.
- Context7 is structurally an untrusted-content channel into the agent (community-contributed docs, closed backend). ContextCrush showed this is not theoretical. Combined with an agent that has file access and network egress it completes the lethal trifecta.
- Agents not calling it unless instructed (the vendor's own admission) means it needs a CLAUDE.md rule or explicit "use context7" prompt to deliver value.

### Gaps
- No independent, controlled evaluation of Context7's effect on hallucinated or outdated API usage was found; the only numbers are the vendor's.
- The history of free-tier cuts (reported as roughly 200/day reduced to 500/month, then raised to 1,000/month in January 2026) was seen only in search snippets of a Medium/DevGenius article that I did not fetch (SNIPPET ONLY); the current plans page confirms only the present 1,000/month figure.
- Whether the "Anthropic verified" badge involved any security review of Context7's content pipeline is undocumented.

## 4. Playwright MCP (Microsoft)

### Takeaway
Playwright MCP lets Claude drive a real browser through accessibility-tree snapshots, which closes the loop on UI work (click through the app, read the page state, fix, repeat); this is widely regarded as genuinely useful, but Microsoft itself now recommends the Playwright CLI plus skills for coding agents on token-efficiency grounds. Claude in Chrome is the alternative when the task needs the developer's own logged-in session, and it is not suited to repeatable verification.

### Cited Findings
- (a) How it works: uses Playwright's accessibility tree rather than pixels, so no vision model is needed; described as "LLM-friendly". Headed by default; `--isolated` keeps the profile in memory; `--caps` opts into vision, PDF, DevTools and testing groups; `--extension` attaches to a running Chrome/Edge. — [microsoft/playwright-mcp README](https://github.com/microsoft/playwright-mcp)
- (a) Security statement from the maintainer: "Playwright MCP is **not** a security boundary"; the `browser_run_code_unsafe` tool "executes arbitrary JavaScript in the Playwright server process and is RCE-equivalent." — [microsoft/playwright-mcp README](https://github.com/microsoft/playwright-mcp)
- (a) Microsoft's own positioning: for coding agents "you might benefit from using the CLI+SKILLS instead"; MCP remains relevant for "specialized agentic loops that benefit from persistent state" such as exploratory automation or self-healing tests. The CLI README calls itself "Token-efficient" ("Does not force page data into LLM") and installs skills for Claude Code via `playwright-cli install --skills`. Neither README gives any numeric benchmark. — [microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp); [microsoft/playwright-cli](https://github.com/microsoft/playwright-cli)
- (c, own measurement) Definition cost: "Playwright MCP has 21 tools using 13.7k tokens (6.8% of Claude's context)" (2 Nov 2025; with default-on tool search in Claude Code this standing cost is now largely deferred). — [Zechner: What if you don't need MCP at all?](https://mariozechner.at/posts/2025-11-02-what-if-you-dont-need-mcp/)
- (c) Ronacher (3 Jul 2025): generating a Playwright script is "significantly quicker" than driving the browser step by step via MCP, but "I find it very hard to replace Playwright with a code approach for all cases", notably when the page is not known in advance. By Dec 2025 he had replaced Playwright MCP with a Playwright skill. — [Ronacher: Tools](https://lucumr.pocoo.org/2025/7/3/tools/); [Ronacher: Skills vs Dynamic MCP Loadouts](https://lucumr.pocoo.org/2025/12/13/skills-vs-mcp/)
- (c) Steve Kinney (course material, last modified 5 Oct 2026): Playwright MCP is the primary runtime tool for agent self-verification; "Chrome DevTools MCP is for the agent to observe. Playwright MCP is for the agent to act."; Playwright MCP "is not logged into Gmail as you"; Claude in Chrome is "the wrong shape" for testing and verification and gets only "an honorable mention" for tasks needing the real session. No token numbers given. — [Steve Kinney: runtime tools compared](https://stevekinney.com/courses/self-testing-ai-agents/runtime-tools-compared)
- (a) Claude in Chrome (official docs, read Nov 2026): shares the browser's login state, reads console errors and DOM, records GIFs, runs in a visible window; requires a direct Anthropic plan (Pro, Max, Ultra, Team, Enterprise) and `/login`, not available via Bedrock/Agent Platform/Foundry or with ZDR; not supported in WSL; "Enabling Chrome by default increases context usage since the browser tools and their instructions are always loaded." A project cannot switch it on ("a repository you check out must not be able to connect Claude to your browser"). — [Claude Code docs: Chrome](https://code.claude.com/docs/en/chrome)
- (a, vendor with a competing product; figures second-hand) Webfuse, 16 Sep 2026: Playwright CLI costs "roughly 1,000 to 2,000 tokens per interaction" after tuning (unnamed practitioners); a Claude Code user's `/context` showed 28.1k tokens (14.1%) of MCP tool definitions; a Chrome DevTools MCP issue reported context jumping from ~31,000 to ~242,000 tokens after one click. MCP-trimming flags (`--image-responses omit` etc.) "do not reduce the accessibility snapshot, the largest cost on complex pages." — [Webfuse: Playwright MCP vs Playwright CLI](https://www.webfuse.com/blog/playwright-mcp-vs-playwright-cli)
- (a) Playwright is listed as an "Anthropic verified" plugin on Claude Marketplace; Chrome DevTools is listed without the badge (page read Nov 2026). — [Claude Marketplace: plugins](https://claude.com/marketplace/plugins)

### Inferences
- The capability (letting the agent see and exercise the UI it just built) is the valuable thing; the transport is secondary. For Claude Code specifically, the Playwright CLI + skill gives the same capability with page data kept out of context unless requested, which is why the maintainer steers coding agents there.
- With tool search on, Playwright MCP's ~13.7k definition cost is mostly moot; the real cost is per-step snapshots on complex pages, which can be several thousand tokens each and accumulate over long sessions.
- Choice rule supported by sources: repeatable verification and cross-browser work → Playwright (CLI first, MCP for long exploratory sessions); diagnosing console/network/performance → Chrome DevTools MCP; anything behind the developer's real login → Claude in Chrome, accepting that it exposes the logged-in browser to prompt injection from page content.
- Any browser tool reading arbitrary web pages is an untrusted-content source; Playwright's explicit "not a security boundary" statement means isolation must come from elsewhere (isolated profile, sandbox, no secrets in the profile).

### Gaps
- No published head-to-head token or success-rate benchmark between Playwright MCP and Playwright CLI was found; Microsoft's claim is qualitative.
- Token figures for Claude in Chrome's tool definitions (~15.4k) and per-page snapshot comparisons (7,400 vs 10,220 tokens) appeared only in search snippets of community reports I did not fetch (SNIPPET ONLY).
- No evidence quantifying how much browser verification improves the correctness of UI work (for example, defect rates with and without it).

## 5. Serena (oraios)

### Takeaway
Serena adds language-server-backed symbol navigation plus symbol-level editing and renaming over MCP; since Claude Code gained an official read-only LSP tool, Serena's unique contribution is narrower (symbolic edits, rename, JetBrains-backed refactoring, memory). There is no independent benchmark showing Serena improves outcomes, and its own maintainers document that recent Claude Code/Opus versions resist using its tools without hooks or a system-prompt override.

### Cited Findings
- (a) Positioning: "A powerful MCP toolkit for coding, providing semantic retrieval and editing capabilities - the IDE for your agent"; agents "operate faster, more efficiently and more reliably, especially in larger and more complex codebases". Tools: find symbol, symbol overview, find referencing symbols, find declaration/implementations, diagnostics, rename, replace symbol body, insert before/after symbol, safe delete. Backends: free language servers ("over 40 programming languages") or "The paid Serena JetBrains Plugin (free trial available)" which alone provides move, inline, type hierarchy and debugging. — [oraios/serena README](https://github.com/oraios/serena)
- (a) Evidence offered by the maintainers is self-assessment by models on "~20 routine coding tasks", for example "cross-file renames, moves, and reference lookups that would cost me 8–12 careful, error-prone steps collapse into one atomic call" (attributed to Opus 4.6 in Claude Code). No token-savings or accuracy numbers are published. — [oraios/serena README](https://github.com/oraios/serena)
- (a, candid maintainer admissions about Claude Code) Serena's docs: recent Claude Code and Opus updates produced "drastically reduced adherence to instructions pertaining to Serena's tools"; built-in tool descriptions make it "almost impossible to convince Opus 4.7 to use Serena"; adding instructions to CLAUDE.md may be "insufficient for counteracting Claude Code's bias towards internal tools"; they "strongly recommend" opt-in hooks (an alpha feature) including a PreToolUse `remind` hook that nudges after repeated grep/read calls and an `auto-approve` hook for `mcp__serena__*`, or overriding the system prompt via `claude --system-prompt=...`. Slow startup may require raising `MCP_TIMEOUT`. — [Serena docs: clients](https://oraios.github.io/serena/02-usage/030_clients.html)
- (a) What the official alternative gives: Claude Code's built-in `LSP` tool (activated by a code-intelligence plugin) can "Jump to a symbol's definition", "Find all references to a symbol", "Get type information at a position", "List symbols in a file", "Search for a symbol by name across the workspace", "Find implementations of an interface", "Trace call hierarchies", and automatically reports type errors after each edit. "The tool is read-only." — [Claude Code docs: tools reference](https://code.claude.com/docs/en/tools-reference.md); [Claude Code docs: code intelligence plugins](https://code.claude.com/docs/en/plugins/code-intelligence.md)
- (b, vendor content marketing, small n; about LSP in general, not Serena) CircleCI blog, 24 Jun 2026: on `vuejs/core` (~149K lines of TypeScript), finding all call sites of three overloaded symbols (11, 20, 260 known references), LSP versus grep in Claude Code on two models. Tool-output tokens fell 31% (Opus 4.8: 18,673 to 12,916) and 33% (Sonnet 4.6: 12,597 to 8,480); time +2% on Opus, −34% on Sonnet; "the LSP was the only configuration that never missed" while Sonnet with grep found 9 of 11 and 249 of 260; Opus found everything either way. The gain required a CLAUDE.md instruction to prefer LSP because Claude defaults to grep; a run without that instruction was not reported. Costs noted: memory (rust-analyzer "several gigabytes"), cold-start indexing, stale state after branch switches. — [CircleCI: Why you should use LSP with Claude Code](https://circleci.com/blog/claude-code-lsp/)
- (d) Hacker News comments mentioning Serena with Claude Code (Aug 2025 – Aug 2026; 9 hits): 3 positive, 2 negative, 4 neutral. Positive: "I've been using Serena MCP to keep my context smaller" (sixothree, 12 Aug 2025); "it can cook with serena mcp" (8note, 3 Feb 2026). Negative: "Serena MCP for example specifically built to not review what it does" and "Even with Serena, Context7, and other MCPs" (ruszki, Aug–Sep 2025). Low volume, no consensus. — [HN Algolia comment search](https://hn.algolia.com/api/v1/search?query=serena%20mcp%20claude%20code&tags=comment&hitsPerPage=30)
- (d, tiny sample; a different MCP, illustrative only) A game developer's C# comparison (10 Mar 2026) of Claude Code's built-in csharp LSP against the JetBrains Rider MCP plugin found LSP responses about 3.1× smaller on average across seven lookups on one 56-line file, with tokens estimated from character counts; the author concluded the tools are complementary ("LSP first"). — [epheria: C# LSP vs JetBrains MCP](https://epheria.github.io/en/posts/CsharpLspVsMcp.en)
- (a) Serena is listed as an "Anthropic verified" plugin on Claude Marketplace (page read Nov 2026). — [Claude Marketplace: plugins](https://claude.com/marketplace/plugins)

### Inferences
- The argument for semantic navigation is sound and has some measured support (CircleCI: fewer tokens, no missed references, biggest gain on weaker models), but that evidence supports "use a language server", which the official LSP plugins now deliver with far less setup. Serena's incremental value over the official plugin is symbol-level *editing* and rename/refactor, plus languages or JetBrains features the official plugins lack.
- Serena fights the harness: when the maintainers themselves say the newest Opus can barely be persuaded to use it and recommend alpha hooks or replacing the system prompt, the practical benefit for a typical Claude Code user is uncertain and the setup burden is real.
- Stronger models narrow the gap (Opus found all references with grep alone), so Serena's benefit likely shrinks with each model generation and matters most in very large, strongly typed codebases or with cheaper models.
- The system-prompt override route trades away Anthropic's tuned instructions, which could degrade other behaviour; this is an inference, not a measured effect.

### Gaps
- No independent benchmark of Serena versus Claude Code's built-in search or versus the official LSP plugins was found.
- A widely repeated "70% token saving" figure for Serena appeared only in a search snippet with no traceable origin (SNIPPET ONLY; not cited as fact). A slimmed fork's claim that Serena's schemas total 7,348 tokens, and an HN comment "I'm considering removing serena MCP, since cc got better with its own tools", were also seen only in snippets (SNIPPET ONLY).
- Setup-pain reports from GitHub issues and Reddit were not reviewed directly; the setup friction cited here comes from Serena's own documentation.

## 6. GitHub MCP server

### Takeaway
For local Claude Code use with a shell, practitioners consistently prefer the `gh` CLI, and the GitHub MCP server was historically the most-cited example of context bloat (~18k–26k tokens); GitHub has since added per-tool selection, read-only mode, lockdown mode and content sanitisation. Its security record includes the best-known MCP prompt-injection demonstration (Invariant Labs, May 2025), which was an architectural "lethal trifecta" problem rather than a code bug.

### Cited Findings
- (a) Structure: remote server "hosted by GitHub and provides the easiest method for getting up and running", or local via Docker/binary. Default toolsets: context, repos, issues, pull_requests, users; about two dozen optional toolsets; `--read-only` skips write tools. "Enabling only the toolsets that you need can help the LLM with tool choice and reduce the context size." — [github/github-mcp-server README](https://github.com/github/github-mcp-server)
- (a) Definition cost: "GitHub: 35 tools (~26K tokens)" (Anthropic, Nov 2025); (d) 27 tools ~18k tokens in one user's Claude Code `/context` (Nov 2025). — [Anthropic Engineering: advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use); [claude-code issue #11364](https://github.com/anthropics/claude-code/issues/11364)
- (a) 10 Dec 2025 hardening: `X-MCP-Tools` header / `--tools` flag to enable individual tools ("~60-90% reduction" in context when loading 3–10 tools); **lockdown mode** (`X-MCP-Lockdown: "true"`) "allowing you to restrict content from untrusted contributors in public repositories" (errors or filters content from users without push access; "Private repositories are unaffected"); **content sanitisation on by default** (strips invisible Unicode, unsafe HTML, hidden text in code fences). — [GitHub changelog 2025-12-10](https://github.blog/changelog/2025-12-10-the-github-mcp-server-adds-support-for-tool-specific-configuration-and-more)
- (c) Versus `gh`: Ronacher says comparing GitHub MCP with the `gh` CLI you will "almost certainly find the latter uses context far more efficiently" (no data); Willison cites GitHub MCP as the canonical context hog and says "Almost everything I might achieve with an MCP can be handled by a CLI tool instead." — [Ronacher: Tools](https://lucumr.pocoo.org/2025/7/3/tools/); [Willison: Claude Skills](https://simonwillison.net/2025/Oct/16/claude-skills/)
- (b) Security: Invariant Labs (Marco Milanta, Luca Beurer-Kellner), 26 May 2025, "toxic agent flow": attacker files an issue containing a prompt injection on the victim's public repo; the user asks the agent to look at open issues; the hijacked agent pulls private-repo data and leaks it via an autonomously created public pull request. Demo used Claude Desktop with Claude 4 Opus and leaked private project details, relocation plans and salary. "this is not a flaw in the GitHub MCP server code itself" but "a fundamental architectural issue that must be addressed at the agent system level." Many users choose "Always Allow", defeating per-call confirmation. Suggested mitigations: least privilege (one repo per session) and monitoring. Note Invariant sells guardrail/scanning products. — [Invariant Labs: GitHub MCP vulnerability](https://invariantlabs.ai/blog/mcp-github-vulnerability)
- (c) Willison on that exploit (26 May 2025): GitHub's MCP server "combines all three ingredients in a single package"; "The bad news, as always, is that I don't know what the best fix for this is"; "My best advice is to be **very careful** if you're experimenting with MCP as an end-user." — [Willison: GitHub MCP exploited](https://simonwillison.net/2025/May/26/github-mcp-exploited/)
- (a) GitHub is listed as an "Anthropic verified" plugin on Claude Marketplace (page read Nov 2026). — [Claude Marketplace: plugins](https://claude.com/marketplace/plugins)

### Inferences
- For a solo developer in a terminal, `gh` covers the same ground with zero standing context, pipeable output and the user's existing auth; the MCP server adds little. The same lethal-trifecta exposure exists with `gh` if the agent reads untrusted issues while holding a broad token, so switching to CLI is not a security fix by itself.
- The MCP server is the better fit where there is no shell or no local credential: cloud/remote sessions, claude.ai connectors, or organisations that want OAuth-scoped, centrally revocable access and lockdown/sanitisation applied server-side.
- Lockdown mode and sanitisation reduce but do not remove injection risk (they filter by contributor trust and strip hidden text; visible malicious instructions from a collaborator, or content in private repos, still pass).

### Gaps
- Later advisories against the server (a lockdown-mode cache issue tracked as PT-2026-52644, CVE-2026-48529, and an unsanitised issue-comment read path in PR #3035) were seen only in search snippets and not verified (SNIPPET ONLY).
- The second half of the README (beyond 100k characters) was not read, so current tool counts and any dynamic-toolset documentation are unverified.
- No measured task-success comparison of `gh` versus GitHub MCP in Claude Code was found.

## 7. Security: documented risks of MCP servers and plugins

### Takeaway
The risks are well documented and have moved from theory to incidents: prompt injection through tool results (GitHub MCP, Context7), tool poisoning through descriptions, a malicious npm MCP server stealing email in the wild (postmark-mcp), critical RCE CVEs in MCP plumbing (mcp-remote) and in Claude Code's own handling of project-supplied hooks and MCP config, and large-scale malicious skills in public registries. Anthropic states plainly that it does not security-audit MCP servers and that an installed plugin can run arbitrary code with the user's privileges, outside the sandbox.

### Cited Findings

Frameworks and attack classes
- (c) Lethal trifecta (Willison, 16 Jun 2025): "Access to your private data", "Exposure to untrusted content", "The ability to externally communicate in a way that could be used to steal your data". MCP "encourages users to mix and match tools from different sources that can do different things." On guardrail products: "95% is very much a failing grade"; "we still don't know how to 100% reliably prevent this from happening"; "The only way to stay safe there is to avoid that lethal trifecta combination entirely." — [Willison: The lethal trifecta](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)
- (b) Tool Poisoning Attacks (Invariant Labs, 1 Apr 2025): "malicious instructions are embedded within MCP tool descriptions", invisible to the user but read by the model. Demo in Cursor: a poisoned `add` tool made the agent read `~/.cursor/mcp.json` and `~/.ssh/id_rsa` and exfiltrate them via a tool parameter. "Rug pull": "a malicious server can change the tool description after the client has already approved it." "Shadowing": one server's description alters behaviour toward a trusted server's tool (emails redirected). — [Invariant Labs: Tool Poisoning Attacks](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks)
- (b) "Line jumping" (Trail of Bits, 21 Apr 2025): "MCP servers can manipulate model behavior without ever being invoked" because tool descriptions enter context at `tools/list`; "tool descriptions themselves are prime vectors for prompt injection"; human oversight degrades into "human-as-the-rubber-stamp"; "treat all MCP connections as potential threats". — [Trail of Bits: Jumping the line](https://blog.trailofbits.com/2025/04/21/jumping-the-line-how-mcp-servers-can-attack-you-before-you-ever-use-them/)

Named incidents and CVEs
- (b) GitHub MCP toxic agent flow, 26 May 2025 (see section 6). — [Invariant Labs](https://invariantlabs.ai/blog/mcp-github-vulnerability)
- (b, reported via trade press; Koi's original post not fetched) postmark-mcp, Sep 2025: an npm package impersonating Postmark's MCP server added one line in v1.0.16 (17 Sep 2025) BCC'ing every email to an attacker address; 1,643 total downloads before removal; Koi Security called it "the world's first sighting of a real-world malicious MCP server." — [The Hacker News: first malicious MCP server](https://thehackernews.com/2025/09/first-malicious-mcp-server-found.html)
- (b) CVE-2025-6514 (JFrog, 9 Jul 2025), CVSS 9.6, `mcp-remote` 0.0.5–0.1.15 (fixed 0.1.16): "a malicious MCP server can respond with a specially crafted `authorization_endpoint` URL value" leading to OS command execution on the client. Advice: "Only connect to trusted MCP Servers, using HTTPS". A Docker blog (vendor) puts mcp-remote at "downloaded more than 437,000 times" (downloads, not compromises). — [JFrog: CVE-2025-6514](https://jfrog.com/blog/2025-6514-critical-mcp-remote-rce-vulnerability/); [Docker: MCP Horror Stories](https://www.docker.com/blog/mcp-horror-stories-the-supply-chain-attack/)
- (b) Claude Code itself (Check Point Research, 25 Feb 2026): (1) hooks in a repo's `.claude/settings.json` ran shell commands without the approval Bash requires; (2) repo settings `enableAllProjectMcpServers` / `enabledMcpjsonServers` could auto-approve MCP servers from `.mcp.json` so a command ran "immediately upon running claude"; (3) `ANTHROPIC_BASE_URL` in project settings exfiltrated the API key "before the victim decides to trust the directory." Tracked as CVE-2025-59536 (published 3 Oct 2025) and CVE-2026-21852 (21 Jan 2026); "All reported issues have been successfully patched prior to this publication"; Anthropic ensured "MCP servers cannot execute before user approval". — [Check Point Research: Caught in the Hook](https://research.checkpoint.com/2026/rce-and-api-token-exfiltration-through-claude-code-project-files-cve-2025-59536/)
- (b) Context7 ContextCrush (Noma, Mar 2026) and CVE-2026-75130 (see section 3). — [Noma Security](https://noma.security/blog/contextcrush-context7-the-mcp-server-vulnerability/); [Context7 response](https://context7.com/guides/contextcrush)
- (b, vendor research) Snyk "ToxicSkills", 5 Feb 2026: of 3,984 skills from ClawHub and skills.sh, "36.82% (1,467 skills) have at least one security flaw", "13.4% of all skills, or 534 in total" have at least one critical issue, and 76 had confirmed malicious payloads (91% using prompt injection; all containing malicious code patterns); a campaign targeted "users of Claude Code and OpenClaw" with 30+ malicious skills. These are open community registries, not Anthropic's marketplaces. Snyk sells the scanner it recommends. — [Snyk: ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)
- (b, PoC by a security vendor; page undated) PromptArmor: a malicious third-party marketplace plugin used a hook to rewrite `settings.local.json` or emit a PreToolUse approval so that "the curl command is executed immediately without requesting approval", then a prompt injection exfiltrated codebase data; `suppressOutput` hid the hook. Requires the user to install the malicious marketplace; a community registry cited states it does not verify individual plugins. — [PromptArmor: Hijacking Claude Code via injected marketplace plugins](https://promptarmor.com/resources/hijacking-claude-code-via-injected-marketplace-plugins)
- (b, PoC by a security vendor) Prompt Security, 5 Jan 2026: a "Python Dependency Helper" plugin from an unofficial marketplace silently redirected an `httpx` install to a trojanised build. "Marketplace trust collapses into one decision."; "Once the plugin is installed, every future session has access to the malicious skill."; "This behaves like compromising your package manager, not like a prompt trick." — [Prompt Security: plugin dependency hijack](https://prompt.security/blog/when-your-plugin-starts-picking-your-dependencies-marketplace-skills-and-dependency-hijack-in-claude-code)

What Anthropic and maintainers say
- (a) "Anthropic reviews connectors against its listing criteria before adding them to the Anthropic Directory, but does not security-audit or manage any MCP server." "We encourage either writing your own MCP servers or using MCP servers from providers that you trust." Plugins can add servers, "so reviewing `.mcp.json` doesn't show every server a session can load." — [Claude Code docs: Security](https://code.claude.com/docs/en/security.md)
- (a) "Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk." — [Claude Code docs: MCP](https://code.claude.com/docs/en/mcp)
- (a) "A Claude Code plugin you install can execute arbitrary code on your machine with your user privileges." Permission rules and the sandbox "cover the tool calls Claude makes, not the code a plugin runs by itself": "Claude Code runs hooks, monitors, MCP servers, LSP servers, and the processes a mod starts outside the sandbox." With auto-update, "the files you reviewed can change on disk." — [Claude Code docs: Plugin security and trust](https://code.claude.com/docs/en/plugins/security.md)
- (a) Playwright MCP "is **not** a security boundary". — [microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp)

### Inferences
- Risk scales with the number of installed servers/plugins and with how many of them ingest third-party content. Each of Context7 (community docs), Playwright/Chrome tools (arbitrary web pages) and GitHub MCP (issues/PR comments from strangers) is an untrusted-content channel; any one of them plus private code plus network egress completes the trifecta.
- Official or "verified" listing is a provenance signal, not a security guarantee: Context7 carried official listing status and still shipped ContextCrush; Anthropic's own wording disclaims verification.
- Auto-update on the official marketplace is a rug-pull surface by design (reviewed files can change); pinning or disabling auto-update trades freshness for reviewability.
- Much MCP security research comes from vendors selling scanners, gateways or guardrails (Invariant/Snyk, Docker, Stacklok, Noma, PromptArmor). The demonstrated attacks are reproducible and credible, but severity framing and "first ever" claims should be read with that incentive in mind. Willison's point that probabilistic guardrails are a failing grade applies to their products too.
- A minimal install set, read-only/least-privilege tokens, isolated browser profiles and sandboxing do more than any detection product.

### Gaps
- No evidence was found of a confirmed in-the-wild compromise via a plugin in Anthropic's official or community marketplace; documented marketplace attacks are proofs of concept via third-party marketplaces.
- Reports seen only in snippets and not verified: a trojanised "Claude Code" extension served via Cursor's extension marketplace on 29 Oct 2026 (BleepingComputer / CSA), a community issue alleging marketplace auto-sync loaded new plugins without consent (closed April 2026), Red Hat's August 2026 plugin-security guidance, and CVEs in Anthropic's reference Git/filesystem MCP servers (SNIPPET ONLY or not found).
- I did not locate a peer-reviewed prevalence study of vulnerabilities across public MCP servers.

## 8. Plugins and marketplaces (including the official marketplace and code-intelligence / LSP plugins)

### Takeaway
Plugins add no new capability: they are a packaging, distribution, versioning and policy layer over skills, subagents, hooks, MCP servers and LSP servers, which is mainly valuable for teams and for one-command installs of someone else's setup. Quality control is light (Anthropic explicitly cannot verify plugin contents; third-party marketplaces are unreviewed), and the only quantitative evidence for the LSP plugins is one small vendor-run test showing fewer tokens and no missed references when Claude is told to prefer LSP.

### Cited Findings

What plugins add
- (a) "A Claude Code plugin is a directory of skills, agents, hooks, MCP servers, or other components that Claude Code installs and loads as one unit." "Skills, subagents, hooks, and MCP servers all work on their own, without a plugin." "Use a plugin when you want several skills, subagents, hooks, or MCP servers packaged as one unit. Install one to get a setup someone else built, with one command and updates from its marketplace. Make one to give your own setup to teammates, install it in many projects, or publish versioned releases." — [Claude Code docs: Plugins overview](https://code.claude.com/docs/en/plugins)
- (a) Standing cost: "An enabled plugin is part of every session, not only the sessions where you use it"; names and descriptions of its skills/agents/commands are in context on every turn; its MCP servers run alongside each session; "what the plugin runs, it runs as you." Official-marketplace plugins show a "Context cost" estimate ("Every turn" and "When invoked"); `claude plugin details <name>` prints the always-on token count; the Installed tab groups plugins "Not used recently". — [Claude Code docs: Plugins overview](https://code.claude.com/docs/en/plugins); [Claude Code docs: Install plugins](https://code.claude.com/docs/en/discover-plugins)
- (a) Team features: project-scope install via committed `.claude/settings.json`; managed settings can "allowlist or block marketplaces, force-install plugins"; plugin dependencies; `claude plugin eval` exists to "compare against a no-plugin baseline". Plugins installed locally do not load in cloud sessions. — [Claude Code docs: Plugins overview](https://code.claude.com/docs/en/plugins); [Claude Code docs index](https://code.claude.com/docs/llms.txt)

Marketplaces and quality control
- (a) Three tiers by name: official (for example `claude-plugins-official`), community (`claude-community`), third-party (everything else). Official/community names are only accepted from `github.com/anthropics/` repos. "A marketplace's name tells you who publishes the catalog, not what each plugin in it does". Community catalog pins "nearly every entry" to a commit SHA and Claude Code refuses a different commit. "Anthropic doesn't review third-party marketplaces". — [Claude Code docs: Plugin security and trust](https://code.claude.com/docs/en/plugins/security.md); [Claude Code docs: Anthropic's marketplaces](https://code.claude.com/docs/en/plugins/anthropic-marketplaces.md)
- (a) The same warning is shown for every plugin regardless of tier: "Anthropic does not control what MCP servers, files, or other software are included in plugins and cannot verify that they will work as intended or that they won't change." — [Claude Code docs: Plugin security and trust](https://code.claude.com/docs/en/plugins/security.md); [anthropics/claude-plugins-official README](https://github.com/anthropics/claude-plugins-official)
- (a) Official marketplace composition: "Most of what it lists comes from partners and other authors rather than from Anthropic"; Anthropic maintains a smaller set "such as `commit-commands`, `code-review`, `feature-dev`, and the language server plugins." It is auto-added on first interactive session and auto-updates by default; the community marketplace must be added manually and does not auto-update by default. — [Claude Code docs: Anthropic's marketplaces](https://code.claude.com/docs/en/plugins/anthropic-marketplaces.md); [Claude Code docs: Install plugins](https://code.claude.com/docs/en/discover-plugins)
- (a) Repo README: "Official, Anthropic-managed directory of high quality Claude Code Plugins"; `/plugins` are Anthropic-developed and "checked on each pull request"; third-party submissions now go through claude.ai/directory/manage and "pull requests are not monitored." (47.4k stars at time of reading; not treated as evidence of usefulness.) — [anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official)
- (a) Claude Marketplace web catalogue showed **532 plugins** (read 16 Nov 2026) and marks some "Anthropic verified". The first 24 in default order were: Frontend Design, Superpowers, Code Review, Context7, Code Simplifier, Playwright, GitHub, CLAUDE.md Management, Feature Dev, Security Guidance, Vercel, TypeScript LSP, Ralph Loop, Claude Code Setup, Commit Commands, Figma, Supabase, PR Review Toolkit, Pyright LSP, Chrome DevTools, Telegram, Atlassian MCP, Slack, Serena; 22 of 24 carried the badge (Figma and Chrome DevTools did not). The docs say the site "shows install counts", but the fetched page text did not expose them, so this is display order, not a verified install ranking. — [Claude Marketplace: plugins](https://claude.com/marketplace/plugins); [Claude Code docs: Anthropic's marketplaces](https://code.claude.com/docs/en/plugins/anthropic-marketplaces.md)

Code-intelligence (LSP) plugins
- (a) "A code intelligence plugin gives Claude the live diagnostics and go-to-definition that your editor has, so Claude catches type errors and missing imports that its own edits introduce before you run your build, and finds definitions and references by symbol instead of by text search." Official plugins: clangd, csharp-ls, gopls, jdtls, kotlin-lsp, lua, PHP (intelephense), pyright, ruby-lsp, rust-analyzer, sourcekit-lsp (Swift), typescript-language-server, plus Shopify's liquid-lsp. The plugin "doesn't include the language server"; the binary must be installed and on `PATH`. — [Claude Code docs: Code intelligence plugins](https://code.claude.com/docs/en/plugins/code-intelligence.md)
- (a) Caveats in the docs: plugin language servers do not start in cloud sessions ("Claude gets no diagnostics or code navigation there"); known symptoms are high memory use during indexing and "False positive diagnostics in a monorepo"; Claude Code proactively offers the plugin through an "LSP plugin recommendation" dialog when a matching binary is already installed. The docs give no numbers for speed, tokens or accuracy. — [Claude Code docs: Code intelligence plugins](https://code.claude.com/docs/en/plugins/code-intelligence.md)
- (b, vendor content marketing, small n) CircleCI, 24 Jun 2026 (details in section 5): tool-output tokens −31% to −33%; LSP "never missed" references whereas Sonnet 4.6 with grep missed some; Opus 4.8 was correct either way and slightly slower with LSP (+2%); total cost across six runs $2.02 (grep) vs $1.88 (LSP); benefits measured only with a CLAUDE.md instruction telling Claude to prefer LSP. — [CircleCI: LSP with Claude Code](https://circleci.com/blog/claude-code-lsp/)

Plugin/marketplace attack research (see section 7): [PromptArmor](https://promptarmor.com/resources/hijacking-claude-code-via-injected-marketplace-plugins); [Prompt Security](https://prompt.security/blog/when-your-plugin-starts-picking-your-dependencies-marketplace-skills-and-dependency-hijack-in-claude-code)

### Inferences
- For a solo developer, a plugin is convenience only; a skill in `~/.claude/skills/` or one `claude mcp add` gives the same capability with more transparency. Plugins earn their keep for teams (project scope, managed allowlists, forced installs, versioned releases, telemetry) and for bundles that are tedious to assemble by hand.
- The LSP plugins are the plugin category with the clearest mechanism and the lowest downside: Anthropic-maintained, read-only navigation, and automatic post-edit diagnostics that give the agent compiler feedback without a build step. Diagnostics after edits are plausibly the larger benefit, but that half is unmeasured.
- The "Anthropic verified" badge and official-marketplace listing should be read as curation and provenance. Documentation never describes a security audit behind them, and Anthropic's warning text is identical across tiers.
- Large plugin bundles re-create the context problem at the skill level: each auto-invocable skill/agent adds its description to every turn. The built-in cost estimates and "not used recently" view exist because this is a real cost.

### Gaps
- No install-count ranking could be verified; the marketplace page's counts were not present in fetched text.
- What "Anthropic verified" requires is not documented in any page read.

## 9. Who benefits most from each item, when to skip it, and a provisional must-use / situational / overhyped ranking

### Takeaway
Nothing in this category is supported by strong independent outcome evidence; the best-supported choices are the low-risk, mechanism-clear ones (an LSP plugin for typed languages, a browser-verification tool for UI work, CLI tools in place of MCP where a CLI exists). Context7, Serena, the GitHub MCP server and large plugin bundles are situational at best for a terminal-based Claude Code user, and "install many MCP servers" as a general strategy is the most overhyped idea given the security record.

### Inferences

Provisional ranking (my synthesis; opinion grounded in the cited evidence, not a measured result)

| Item | Verdict | Best for | Skip when |
|---|---|---|---|
| Official code-intelligence (LSP) plugin for your language | Closest to must-use for typed languages in medium/large codebases (evidence: clear mechanism, one small vendor test, low risk) | Experienced developers and teams on TypeScript, Go, Rust, Java, C#, Python with types; weaker/cheaper models benefit most | Small scripts, dynamic untyped code, cloud sessions (servers do not start), monorepos that trigger false diagnostics, memory-constrained machines |
| Browser verification for UI work (Playwright CLI + skill first; Playwright MCP for long exploratory sessions) | Must-use *capability* for front-end work; the MCP form is situational | Anyone building web UIs, including beginners (closes the "does it actually render" loop) | Back-end, CLI or library work; if you only need a logged-in session use Claude in Chrome instead |
| Claude in Chrome | Situational | Quick checks that need your real login state; demo GIFs | Repeatable testing; WSL; Bedrock/Agent Platform/Foundry or ZDR accounts; security-sensitive browser profiles |
| `gh` CLI (in place of GitHub MCP) | Default choice in a terminal | Solo and experienced developers with local auth | No shell available |
| GitHub MCP server | Situational | Cloud/remote sessions, claude.ai connectors, organisations wanting OAuth-scoped access with lockdown mode | Local terminal use where `gh` exists; public repos with untrusted issue traffic unless lockdown/read-only is on |
| Context7 | Situational (leaning overhyped as a default install) | Beginners and anyone on fast-moving frameworks newer than the model's cutoff; lower token cost than web search | Stable or well-known libraries; private/internal libraries (paid); strict supply-chain posture; if you would not add a rule telling Claude to use it |
| Serena | Situational, trending overhyped for Claude Code specifically | Very large typed codebases needing symbol-level edits/renames; JetBrains users wanting IDE refactorings; non-Claude harnesses | Typical Claude Code use with a current Opus model (maintainers say adherence is poor); anyone unwilling to maintain hooks or a system-prompt override; small projects |
| Plugins/marketplaces as a mechanism | Situational: high value for teams, low for solo users | Teams standardising setup, admins enforcing policy | Solo users who can drop in a skill or a single MCP server directly |
| Large third-party plugin bundles and community skill registries | Overhyped / highest risk | Only after reading hooks, `.mcp.json` and `bin/` | Default; especially unofficial marketplaces |
| "Install lots of MCP servers" as a strategy | Overhyped | Rarely | Almost always: each added server is attack surface and (without tool search) context cost |

By persona
- Solo beginner: start with zero MCP servers; add an LSP plugin if prompted and a browser tool if doing web UI; consider Context7 only when visibly hitting outdated-API errors. Beginners are least equipped to audit plugins, so stay inside the official marketplace and avoid auto-approving tool calls.
- Experienced developer: prefer CLIs and self-written skills (the Ronacher/Willison/Zechner pattern); LSP plugin for typed code; Playwright CLI; keep at most one or two MCP servers that have no CLI equivalent.
- Team/organisation: this is where MCP and plugins have their strongest case (remote OAuth servers, managed allowlists, project-scope plugins, a private marketplace). Budget for review: pin versions, disable auto-update for anything not first-party, and treat every content-ingesting server as a lethal-trifecta contributor.

Other inferences
- The trend through 2025–2026 is convergence on "skills + CLI" for local coding and "remote MCP with OAuth" for governed service access; several MCP maintainers (Microsoft Playwright, Upstash Context7, Sentry) now ship both forms.
- Because model capability keeps eroding the marginal value of navigation and docs add-ons (Opus found all references with grep; newer models know newer APIs), any ranking here should be re-checked every few months.

### Gaps
- No add-on in scope has independent, controlled evidence of improved end-to-end task outcomes in Claude Code; the ranking rests on mechanism, small vendor-run tests and practitioner reports.
- Reddit community signal (r/ClaudeAI, r/ClaudeCode) was not accessible; Hacker News volume on these specific tools was low (9 relevant comments for Serena), so community consensus is not established.
- Cost-of-setup and failure-rate data (how often installs break, time lost to configuration) were not found for any item beyond maintainers' own troubleshooting notes.
