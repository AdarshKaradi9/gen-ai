## Core claims (3-7 bullets, what the video argues)
- "Vibe coding" (term coined by Andrej Karpathy; the video is dated March 26, 2025) means giving in to the vibes, "embrace exponentials, and forget that the code even exists" - i.e. letting AI write everything.
- Coding and programming are not the same thing: coding (translating logic into syntax) is being made obsolete by LLMs; programming (ingenuity, creativity, instincts, knowing what to remove) is not.
- Vibe coding without understanding the code fails in production; the cautionary example is an indie hacker whose vibe-coded SaaS with paying customers was hacked ("maxed out usage on API keys, people bypassing the subscription, creating random [entries] on DB"), taken down permanently, and "the guy had to beg for his job back at Popeyes."
- Done properly it can work; the video predicts "a billion-dollar business that runs entirely on Vibes" built with v0/Bolt plus AI IDEs like Cursor and Windsurf.
- Three rules for proper vibe coding: (1) pick a popular, simple stack; (2) get good at Git (non-negotiable); (3) act as the product manager for your AI.
- Pieter Levels' vibe-coded flight-sim MMO is held up as the trend's origin and as a product that "would have failed miserably" without his years of experience.

## Specific tactics (concrete, actionable; include numbers, prices, timings, exact UI choices)
- Rule 1: choose a popular, simple stack (React, Express, Tailwind, Redis, Deno named) because LLMs are best at problems already solved on GitHub/Stack Overflow; a fancy new framework "is going to kill your vibes." Fireship admits he prefers Svelte and gets good results with Vue/Nuxt, so "this rule is breakable."
- Rule 2 (unbreakable): use version control religiously because AI "has the power to delete your working code" and it is "almost impossible to prompt it back into existence." Tools like Claude Code can commit for you.
- Rule 3 (most important): "You're not a coder anymore. You're a product manager." Break requirements into small, highly specific steps; supply context (recent docs, UI images); aim for the LLM to be "as deterministic as possible" - "you don't want your LLM to get creative."
- Sponsor segment: Grammarly for PR descriptions, emails, Slack replies (not a product tactic).
