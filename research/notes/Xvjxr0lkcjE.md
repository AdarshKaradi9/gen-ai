## Core claims (3-7 bullets, what the video argues)
- Official description: "The average app loses 77% of new users within three days of install," so many users never get far enough to experience the app's full value before churning.
- The video focuses on "the moment when the user experiences the app's core action and realizes how it adds value to their life" - Google Play's definition of activation.
- Chapter structure (from the description): 00:00 What is user activation & commitment; 00:52 Prioritize your app's core action; 01:30 Create a core action habit loop; 02:24 Help your users set goals; 02:59 Embrace different types of commitment; 03:44 Conclusion.
- Google Play's user-journey framework (from the Medium series snippets): an activated user is "an onboarded user who has interacted with the core action of the app enough to understand its value"; "onboarding educates users about your app; activation is making sure they got it!"; commitment is the stage after activation where the goal is to keep users engaged.

## Specific tactics (concrete, actionable; include numbers, prices, timings, exact UI choices)
- Inferred from chapter titles only (not verified against the video body): identify one core action and prioritize getting new users to it; wrap that action in a habit loop (cue → action → reward); let users set goals inside the app; support several kinds of commitment (not only subscriptions).
- Related Google Play written guidance (same team, not this video): keep onboarding fast with minimal input and defer registration later in the funnel (Freeletics did this and saw +58% user activity in the first 7 days); explain available notifications during onboarding and let users manage preferences (Aftenposten cut uninstalls 9.2% over 60 days and reduced full muting by 28%); reward the most engaged users (beta access, badges, in-app-only promo codes); personalize notifications by cohort and timing.
- Google's "Engage and retain" page: respond to reviews (users raise ratings by +0.7 stars on average when developers reply), use the in-app review API to choose the prompt moment, run live-ops time-limited events, use app links to deep-link into key content.
