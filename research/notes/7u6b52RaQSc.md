## Core claims (3-7 bullets, what the video argues)
- Engineering is no longer the bottleneck for a solo founder; distribution and validation are. "Distribution is the issue now" (his newsletter).
- Build small, validate before coding, ship an MVP, learn from real users, iterate; avoid feature bloat.
- Learn by building real product features (project-based learning), not by chaining tutorials.
- Build in public: spend roughly 20-30% of your time creating content about the build so you have a distribution funnel by launch day.
- Use AI coding assistants with an explicit planning step first; plan features into steps before generating code.
- Pick popular, boring stacks so documentation and AI assistants work well.
- If you lack UX skill, use templates or copy proven designs rather than designing from scratch; AI-generated designs "suck" (his newsletter).

## Specific tactics (concrete, actionable; include numbers, prices, timings, exact UI choices)
- Idea: list 5-10 real problems from your own life; if none, copy an existing product with proven demand.
- Validate with a landing page and collect signups before building (can also be used to pitch investors). His own waitlist site: first tried Framer + Formspark (poor experience), then rebuilt in Next.js with Supabase and Resend for email.
- Learning order recommended: HTML -> CSS -> JavaScript -> React -> Next -> Node -> Express -> MongoDB (MERN). Resources: The Odin Project (free), roadmap.sh, Zero To Mastery (paid, affiliate).
- AI tooling: pick one assistant (Cursor ~ $20/month, Claude Code, GitHub Copilot, Warp); use a "plan mode"/"ultra think" step to break features into steps, then generate code. Uses Notability to sketch features/plans. Used Manus to analyze the MVP and suggest pricing and features (newsletter).
- Mobile: reuse the web stack; React Native + Expo to ship iOS/Android quickly; Supabase for backend and auth. He demos setting a mobile app up "in a few minutes."
- Deployment: Vercel or Netlify for web (Vercel popular but pricier); Expo for store submission; Stripe for payments.
- Pricing: subscription (monthly/yearly) or one-off fee; always offer a free trial.
- Go-to-market: build in public on X, YouTube, Instagram (he also set up separate Instagram/TikTok pages for the app, planning organic short-form first, paid ads maybe later); launch on Product Hunt and Reddit (share the story, ask for testers); clarify target customer, tone and core story.
- Naming: spent 1-2 weeks on the name (considered "Hobbyism", "Anti brain rot journal", settled on "Polymath").
- Costs so far (newsletter): essentially only Supabase, coding-agent subscriptions (some via partnerships/credits) and the domain.
